## Method

`feature/v1.1-e` was never pushed to GitHub (only through `feature/v1.1-c` exists on `origin`), so a `git
pull`/`fetch`+checkout of this exact commit was not possible on the remote hosts. Each remote host's existing
checkout was either dirty (server-a, 106 modified files on stale `main`) or clean-but-on-an-unrelated
commit (macbook-agent), so per the task's explicit instruction neither was reset/cleaned/pulled. Instead, `git
archive 1d4c668 -- agent` was piped over SSH into a disposable `/tmp` directory on each host, and `pip install
-e <that path>` was run into the **existing venv that the host's real running service already uses** — this
upgrades the live install in place with the exact tested commit's code, without touching either host's git
checkout at all. The disposable source trees were deleted after testing.
