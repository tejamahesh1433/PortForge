# PortForge v1.3.0

PortForge v1.3.0 adds host lifecycle operations for Central and the dashboard while retaining protocol 1 and agent contract 1 compatibility. These notes describe the release candidate; they do not indicate that production has been upgraded.

## Highlights

- **Remove Record** administratively purges a Central host record and its Central-side dependents, and invalidates that host’s agent credential.
- After Remove Record, the previous agent credential is rejected; reconnect requires **explicit re-enrollment**. The same preserved host UUID may reclaim the identity with a new credential.
- **Add Host** mints enrollment tokens through a dashboard server-side BFF so the admin/bootstrap secret never reaches the browser.
- **Recheck Status** refreshes host health from Central only — it does not wake machines, restart agents, or force remote heartbeats.
- An isolated **`portforge-dev`** compose project (API `:58001`, dashboard `:3001`, disposable Postgres `:55433`) keeps feature work off frozen production (`portforge` / `:58000` / `:3000` / `:55432`).
- Generic localhost vs LAN onboarding guidance and operator runbooks cover Add Host, Remove Record, re-enrollment, Recheck Status, agent service management, upgrade, and rollback.

## Compatibility

- Protocol version: **1**
- Agent contract version: **1**
- Database migration: **none**
- Existing host identity semantics are preserved (including same-UUID re-enrollment after Remove Record).

## Explicit limitations

- Remove Record is **not** permanent Decommission / tombstone.
- Remove Record does **not** stop, uninstall, wake, or remotely control the agent process.
- No browser authentication is introduced; dashboard/API remain intended for localhost, trusted LAN, or private VPN only.
- Do not expose PortForge directly on the public Internet.

## Upgrade notes

Upgrade Central and agents using the normal deployment process only after release authorization. Protocol 1 agents and contract 1 clients remain compatible. No database migration is required for v1.3.0.

For development of further changes, use `docker-compose.dev.yml` / project `portforge-dev` — do not rebuild the production compose project casually.

## Known limitations

- Permanent Decommission lifecycle state is future work.
- Remote agent stop / uninstall / wake / auto-update are out of scope.
- Dashboard remains without browser authentication.
