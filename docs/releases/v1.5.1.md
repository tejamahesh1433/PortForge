# PortForge v1.5.1

Agent-only patch release for a macOS LaunchAgent lifecycle defect discovered after v1.5.0 production rollout.

Base: published v1.5.0 (`fb23b0220a2a680559fac0a636f3ced3b756a7ac`).

---

## FIXED

### macOS LaunchAgent KeepAlive / kickstart hardening

- Generated LaunchAgent now sets:
  - `KeepAlive.SuccessfulExit = false` (unchanged intent: clean stop stays stopped for operator `service stop`)
  - `KeepAlive.NetworkState = true` (recover when network returns after sleep/wake)
- `portforge agent service status` treats launchd `state = running` as healthy; loaded-but-not-running as failure.
- `portforge agent service start` (kickstart):
  - 60s timeout
  - if kickstart times out, re-check running state before failing
  - if kickstart fails and plist exists, one bootstrap + kickstart retry

This addresses the post-v1.5.0 incident where Mac went OFFLINE after a clean agent exit and stayed stopped until manual bootstrap.

---

## DEFERRED

### Linux upgrade false FAILED (`systemctl --user restart` rc=-15)

Self-restart from inside the user unit can surface `returncode=-15` (SIGTERM) while systemd still starts the new agent. Host becomes healthy on the new version with a false FAILED upgrade row.

Not fixed in v1.5.1. Needs non-blocking/detached restart plus truthful SUCCEEDED completion (see Windows item). Evidence: `docs/qualification/v1.5.1-rc.md`.

### Windows (and general) upgrade stuck at RESTARTING

Agent reports through RESTARTING then exits; Central does not infer SUCCEEDED from a matching heartbeat; new process never re-sees the upgrade. Host can be HEALTHY on the target version while the upgrade row stays RESTARTING.

Not fixed in v1.5.1. Requires Central reconciliation (or explicit post-restart agent status) with strict host/version/state guards. Evidence: `docs/qualification/v1.5.1-rc.md`.

## Upgrade notes

1. Keep Central/Dashboard on v1.5.0.
2. Upgrade **agents** to the v1.5.1 wheel (especially macOS).
3. On macOS after install, reinstall the LaunchAgent so the new plist is written:

```bash
portforge agent service uninstall
portforge agent service install
portforge agent service start
```

4. Do not rewrite historical FAILED/RESTARTING upgrade rows; they remain historical.
