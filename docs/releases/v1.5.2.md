## FIXED / ADDED

### Upgrade reconciliation (Phase 20)

- Linux self-restart handoff (`systemctl --user restart --no-block`)
- Windows restart handoff via allowlisted Scheduled Task helper
- Central heartbeat reconciliation: `RESTARTING → VERIFYING_HEALTH → SUCCEEDED`
  when reported version exactly matches target
- Terminal-state immutability (`SUCCEEDED` / `FAILED` / `ROLLED_BACK`)
- Stale-attempt and host-identity protection; concurrent reconcile safety

### Recovery, retry, fleet rollout (Phase 21)

- Stuck-upgrade detection (state buckets vs `updated_at`)
- Typed transient download retry with bounds and backoff; permanent failures
  (checksum, invalid artifact) never auto-retry
- Operator retry creates a **new** attempt row (FAILED history immutable)
- Safe cancel before install/restart critical sections
- Fleet rollouts via shared `request_id`: canary, bounded concurrency,
  stop-on-failure, partial results, offline/decommissioned/current-host policies

### Observability and operator controls (Phase 22)

- Typed `UpgradeStatusOut` separating runtime health from control-plane history
- Waiting/failure codes and operator-facing explanations
- Safe action derivation (`VIEW` / `RETRY` / `CANCEL` / `ROLLBACK`)
- CLI: `portforge upgrade status|retry|cancel|rollout`
- Dashboard fleet + host upgrade status panels (BFF; no browser admin secret)
- Activity-event audit with idempotent SUCCEEDED/FAILED/cancel/retry

## LIMITATIONS

1. Agent local download retry/backoff is not visible to Central until FAILED.
2. Fleet rollout policy is not persisted (re-supplied on `advance`); canary
   membership is not a durable column.
3. MCP mutating and read-only fleet/upgrade tools remain deferred.
4. Historical terminal `FAILED` / `ROLLED_BACK` rows are never auto-rewritten
   even if runtime later matches the old target — use operator retry for a new
   attempt when appropriate.
5. Physical macOS upgrade smoke for this RC: **SKIPPED** (no disposable Mac);
   LaunchAgent generator and unit tests remain at the v1.5.1 KeepAlive form.
6. Production-derived DB restore rehearsal: **SKIPPED** (no sanitized backup
   available in this environment).
